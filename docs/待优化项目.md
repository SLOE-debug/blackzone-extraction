# 大锤跌落伤害与强力旋风打散重构方案

## 一、最终产品目标

本轮不是继续小幅微调参数，而是明确建立两个战斗规则：

```text
怪物被掀飞后：
落地必须受到与撞击速度对应的跌落伤害。

怪物被旋风击飞后：
必须能够撞开外层怪物；
A撞B、B撞C后，C仍然有肉眼可见的轻微位移；
旋风结束时，原本密集的怪群必须明显散开。
```

旋风最终定位：

> 一次高强度的怪群扰乱技能。它不仅造成伤害，还会改变大量怪物的位置、队形和进攻节奏。

# 二、第一部分：增加真实跌落伤害

## 2.1 当前问题

当前腾空落地流程为：

```text
计算重力
→ 高度小于等于零
→ 高度归零
→ 垂直速度归零
→ 水平飞行速度归零
→ 结束腾空
```

没有任何落地伤害结算。

需要改成：

```text
计算落地瞬间向下速度
→ 判断是否超过伤害阈值
→ 根据撞击速度计算跌落伤害
→ 调用怪物伤害接口
→ 播放落地受击反馈
→ 清空腾空状态
```

## 2.2 新增通用落地配置

新增文件：

```text
assets/bundles/battlefield/combat/effects/
battlefield-airborne-impact-config.ts
```

内容建议：

```ts
export interface BattlefieldAirborneImpactConfig {
  readonly minimumDamageImpactSpeed: number;
  readonly fullDamageImpactSpeed: number;
  readonly minimumDamageScale: number;
  readonly maximumDamageScale: number;
}

export const BATTLEFIELD_AIRBORNE_IMPACT_CONFIG = Object.freeze({
  minimumDamageImpactSpeed: 5.5,
  fullDamageImpactSpeed: 13,
  minimumDamageScale: 0.3,
  maximumDamageScale: 1,
}) satisfies Readonly<BattlefieldAirborneImpactConfig>;
```

含义：

```text
落地速度小于5.5：
不造成跌落伤害，避免轻微腾空也受伤。

落地速度5.5～13：
伤害随速度平滑提高。

落地速度大于等于13：
达到完整跌落伤害。
```

## 2.3 扩展方向腾空契约

修改：

```text
assets/core/contracts/monster-effects.ts
```

将：

```ts
export interface DirectionalLaunchEffect {
  readonly directionX: number;

  readonly targetHeight: number;

  readonly horizontalDrag: number;
  readonly gravityScale: number;

```

改为：

```ts
  readonly horizontalDrag: number;
  readonly gravityScale: number;

  /**
   * 用于落地伤害计算的基础伤害。
   * 零表示本次腾空不会造成跌落伤害。
   */
  readonly landingDamageBase: number;
}
```

## 2.4 增加落地伤害状态

在 `BattlefieldMonsterEffectGroupState` 中增加：

```ts
public readonly landingDamageBase: Float32Array;
```

构造时：

```ts
this.landingDamageBase = new Float32Array(count);
```

启动方向腾空时：

```ts
state.landingDamageBase[entityId] = Math.max(
  state.landingDamageBase[entityId] ?? 0,
  effect.landingDamageBase,
);
```

如果同一只怪物在空中再次被掀飞，不要把更高的待结算跌落伤害覆盖成更低值。

## 2.5 上挑传入跌落伤害

在 `SledgehammerProgressionStats` 增加：

```ts
readonly uppercutLandingDamageScale: number;
```

建议：

```ts
uppercutLandingDamageScale: 0.9,
```

在大锤命中结算中：

```ts
this.monsters.applyDirectionalLaunch(
  populationId,
  entityId,
  {
    directionX,
    directionZ,
    targetHeight: launchHeight,
    horizontalSpeed:
      SLEDGEHAMMER_PROGRESSION.uppercutHorizontalSpeed,
    horizontalDrag:
      SLEDGEHAMMER_PROGRESSION.uppercutHorizontalDrag,
    gravityScale: 1,
    landingDamageBase:
      definition.baseDamage
      * SLEDGEHAMMER_PROGRESSION.uppercutLandingDamageScale,
  },
);
```

这样当前群体上挑形成：

```text
上挑直接伤害：1.2倍基础伤害
落地伤害：最高约0.9倍基础伤害
```

完整命中最高约：

```text
2.1倍基础伤害
```

但第二段伤害需要怪物真正落地后才发生，因此有明确的延迟收益。

## 2.6 在落地瞬间结算

修改：

```text
battlefield-monster-effect-runtime.ts
```

在 `updateAirborne()` 中，不要先把 `velocity` 归零。

建议逻辑：

```ts
const effectiveGravity =
  this.gravity * (state.gravityScale[entityId] ?? 1);

const nextVelocity =
  velocity - effectiveGravity * deltaTime;

const nextElevation =
  elevation + nextVelocity * deltaTime;

if (nextElevation <= 0 && nextVelocity <= 0) {
  const impactSpeed = -nextVelocity;

  this.resolveLandingDamage(
    state,
    entityId,
    impactSpeed,
  );

  elevation = 0;
  velocity = 0;
  airborne = false;

  state.airborneVelocityX[entityId] = 0;
  state.airborneVelocityZ[entityId] = 0;
  state.airborneHorizontalDrag[entityId] = 0;
  state.landingDamageBase[entityId] = 0;
} else {
  elevation = nextElevation;
  velocity = nextVelocity;
}
```

增加：

```ts
private resolveLandingDamage(
  state: BattlefieldMonsterEffectGroupState,
  entityId: number,
  impactSpeed: number,
): void {
  const baseDamage =
    state.landingDamageBase[entityId] ?? 0;

  if (baseDamage <= 0) {
    return;
  }

  const config =
    BATTLEFIELD_AIRBORNE_IMPACT_CONFIG;

  if (impactSpeed
    < config.minimumDamageImpactSpeed) {
    return;
  }

  const range = Math.max(
    0.001,
    config.fullDamageImpactSpeed
      - config.minimumDamageImpactSpeed,
  );

  const normalized = Math.max(
    0,
    Math.min(
      1,
      (
        impactSpeed
        - config.minimumDamageImpactSpeed
      ) / range,
    ),
  );

  const eased =
    normalized * normalized * (3 - 2 * normalized);

  const damageScale =
    config.minimumDamageScale
    + (
      config.maximumDamageScale
      - config.minimumDamageScale
    ) * eased;

  state.group.damageMonster(
    entityId,
    baseDamage * damageScale,
  );
}
```

## 2.7 跌落反馈

伤害接口现有受击闪烁应继续触发。

另外建议增加一个轻量落地反馈：

```text
怪物身体快速压缩再恢复；
落地点生成小型尘土环；
播放低频撞地声；
重型怪物落地声音更沉。
```

不要增加长时间全屏震动。

玩家需要明确感知：

```text
上挑伤害
和
落地伤害
是两次不同的收益。
```

# 三、第二部分：旋风击退改成特别明显

## 3.1 当前数值不再进行小幅调整

当前大约是：

```text
早期脉冲初速度：9.72
后期脉冲初速度：14.58
终结初速度：22.28
最高速度：38
持续时间：0.4秒
```

对于用户要求的“明显搅乱和打散”仍然偏保守。

建议第一轮直接提升至：

```ts
spinKnockbackImpulse: 18,

spinPulseMinimumKnockbackScale: 0.8,
spinPulseMaximumKnockbackScale: 1.35,

spinFinalKnockbackScale: 2,

spinMaximumKnockbackSpeed: 52,
spinKnockbackDurationSeconds: 0.55,
```

得到：

```text
早期脉冲：14.4
后期脉冲：24.3
最终爆散：36
最高累积速度：52
```

这属于显著调整，而不是难以察觉的微调。

## 3.2 旋风脉冲不要只做纯径向击退

纯径向击退会让所有怪整齐向外移动，不一定产生“搅乱”的感觉。

脉冲方向应同时包含：

```text
径向向外分量；
沿旋转方向的切向分量。
```

增加配置：

```ts
readonly spinPulseRadialWeight: number;
readonly spinPulseTangentialWeight: number;
```

推荐：

```ts
spinPulseRadialWeight: 0.82,
spinPulseTangentialWeight: 0.57,
```

旋风普通脉冲：

```ts
const radialX = normalizedTargetX;
const radialZ = normalizedTargetZ;

const tangentX = -radialZ;
const tangentZ = radialX;

const mixedX =
  radialX
    * progression.spinPulseRadialWeight
  + tangentX
    * progression.spinPulseTangentialWeight;

const mixedZ =
  radialZ
    * progression.spinPulseRadialWeight
  + tangentZ
    * progression.spinPulseTangentialWeight;

normalize(mixedX, mixedZ);
```

最终打击仍使用纯径向方向。

结果应是：

```text
旋风过程中：
怪物沿螺旋轨迹向外移动并彼此碰撞。

旋风结束时：
最终打击把剩余怪物直接向外炸散。
```

这样比单纯提高数字更接近“搅乱怪群”。

# 四、第三部分：保证 A → B → C 仍有明显传播

## 4.1 当前传播衰减问题

当前传递公式：

```ts
transferredSpeed =
  closingSpeed
  * 0.68
  * targetKnockbackScale;
```

假设 A 速度为 20：

普通怪物：

```text
A → B：13.6
B → C：9.25
```

如果目标是击退倍率约 `0.58` 的重型怪物：

```text
A → B：7.89
B → C：3.11
```

第二层已经低于当前 `3.2` 的传播阈值，因此后续很容易停止。

这就是代码有传播、玩家却看不明显的根本原因。

## 4.2 传播使用软化后的抗性

直接被锤子命中时，可以继续使用完整击退抗性。

但“被另一只高速怪物撞击”时，不应每层都乘完整抗性，否则连锁会指数衰减。

增加：

```ts
function calculateKineticResistance(
  knockbackScale: number,
): number {
  const scale = Math.max(
    0,
    Math.min(1, knockbackScale),
  );

  return 0.65 + scale * 0.35;
}
```

例如重型怪物：

```text
原击退倍率：0.58
传播有效倍率：0.853
```

它依然比普通怪物更难推动，但不会直接变成动量墙。

## 4.3 提高传播参数

修改：

```text
battlefield-kinetic-propagation-config.ts
```

建议：

```ts
durationSeconds: 1,

transferRatio: 0.84,
sourceRetention: 0.8,

minimumSpeed: 1.2,
maximumSpeed: 52,

maximumGeneration: 10,
maximumCarriersPerSkill: 128,

pairCooldownSeconds: 0.06,

propagatedKnockbackDurationSeconds: 0.48,

propagationFloorSpeed: 9,
propagationFloorDecay: 0.62,
minimumPropagationFloorSpeed: 1.5,
```

需要在配置接口中增加后四个字段。

## 4.4 为前几层设置最低传播速度

只提高传递率仍然无法保证 C 一定移动。

增加按传播代数衰减的最低速度：

```ts
function calculatePropagationFloor(
  generation: number,
  config: BattlefieldKineticPropagationConfig,
): number {
  return Math.max(
    config.minimumPropagationFloorSpeed,
    config.propagationFloorSpeed
      * Math.pow(
        config.propagationFloorDecay,
        Math.max(0, generation - 1),
      ),
  );
}
```

建议结果：

```text
A → B，B成为第1代：
最低速度9

B → C，C成为第2代：
最低速度5.58

C → D，D成为第3代：
最低速度3.46

D → E，E成为第4代：
最低速度2.14

E → F，F成为第5代：
最低速度1.5
```

这保证：

```text
B被明显撞开；
C仍有清晰位移；
D、E继续产生逐渐减弱的传播。
```

不会出现第二层以后突然完全停止。

## 4.5 修改传递公式

在计算目标速度前，先确定下一代：

```ts
const nextGeneration =
  (sourceState.kineticGeneration[sourceEntity] ?? 0)
  + 1;
```

然后：

```ts
const resistance =
  calculateKineticResistance(
    targetState.group
      .launchResponse.knockbackScale,
  );

const physicalTransferredSpeed =
  closingSpeed
  * config.transferRatio
  * resistance;

const propagationFloor =
  calculatePropagationFloor(
    nextGeneration,
    config,
  );

const transferredSpeed = Math.min(
  config.maximumSpeed,
  Math.max(
    physicalTransferredSpeed,
    propagationFloor,
  ),
);
```

最低速度只在以下条件满足时生效：

```text
来源仍是有效动量载体；
来源真实闭合速度大于1.2；
两只怪确实发生碰撞；
传播代数没有超过上限。
```

不能让静止重叠的怪物凭空获得速度。

## 4.6 延长传播获得的击退时间

当前 `writeKnockbackVelocity()` 只保证至少 `0.2` 秒。

修改为接收配置：

```ts
function writeKnockbackVelocity(
  state: BattlefieldMonsterEffectGroupState,
  entityId: number,
  velocityX: number,
  velocityZ: number,
  maximumSpeed: number,
  minimumDuration: number,
): void
```

调用时：

```ts
writeKnockbackVelocity(
  targetState,
  targetEntity,
  nextVelocityX,
  nextVelocityZ,
  config.maximumSpeed,
  config.propagatedKnockbackDurationSeconds,
);
```

内部：

```ts
const remaining = Math.max(
  state.knockbackRemaining[entityId] ?? 0,
  minimumDuration,
);
```

否则 C 虽然获得速度，但只持续很短时间，视觉上依然不明显。

# 五、第四部分：让旋风真正打散怪群

## 5.1 不以“发生传播”为验收标准

不能再使用：

```ts
expect(target.x).toBeGreaterThan(startX);
```

因为移动 `0.001` 也会通过。

测试必须约束实际位移。

## 5.2 直线传播验收

场景：

```text
A、B、C、D沿直线排列；
A被旋风直接命中；
B、C、D都没有被锤头直接命中。
```

要求在 0.8 秒内：

```text
A总位移 ≥ 4米；
B总位移 ≥ 2米；
C总位移 ≥ 0.6米；
D总位移 ≥ 0.2米。
```

重型怪物参与时：

```text
B为重型怪物：
B总位移 ≥ 1.2米；

C位于B后方：
C总位移 ≥ 0.35米。
```

## 5.3 环形怪群验收

在玩家周围生成三圈怪：

```text
内圈：12只
中圈：24只
外圈：36只
```

旋风结束后：

```text
至少70%的怪物离开初始位置2米以上；
内圈怪物平均距离玩家增加至少3米；
怪群二维凸包面积增加至少80%；
至少存在三层有效传播；
不存在大批怪物原地重叠或被外圈完全挡住。
```

## 5.4 搅乱程度验收

旋风前后对怪物极角排序进行比较。

不能要求所有怪物保持原有径向顺序。

建议验收：

```text
至少30%的存活怪物在旋风后，
与旋风前相比更换了相邻怪物。
```

这用于验证切向击退确实造成了怪群内部重排，而不只是整齐扩大圆环。

# 六、必须增加的自动化测试

## 6.1 跌落伤害存在

```text
方向腾空高度4.2；
基础落地伤害90；
等待怪物落地；
必须产生一次大于零的额外伤害；
落地伤害只能结算一次。
```

## 6.2 低高度不造成跌落伤害

```text
撞击速度低于5.5；
落地后伤害事件数量不增加。
```

## 6.3 高处跌落伤害更高

```text
目标高度1米与4.2米分别测试；
4.2米落地伤害必须高于1米。
```

## 6.4 怪物空中死亡

```text
怪物被掀飞；
空中受到伤害并死亡；
落地时不得再次对死亡实体结算伤害。
```

## 6.5 空中再次被掀飞

```text
怪物第一次掀飞后尚未落地；
再次施加更强掀飞；
最终只结算一次落地伤害；
保留两次中的较高基础落地伤害。
```

## 6.6 三层传播强度

不要只判断位置增加。

测试：

```text
A位移 ≥ 4；
B位移 ≥ 2；
C位移 ≥ 0.6。
```

## 6.7 重型目标传播

```text
A为普通怪；
B为重型怪；
C为普通怪；

A撞B后B必须明显移动；
B撞C后C仍然必须移动。
```

## 6.8 传播不会无限持续

```text
经过3秒后：
所有动量载体生命周期归零；
所有击退速度最终归零；
不存在永久滑动实体。
```

## 6.9 旋风终结爆散

```text
同一目标记录终结命中前后的速度；
终结命中后速度必须明显提高；
速度不得超过52。
```

## 6.10 切向扰乱

```text
位于玩家正右侧的怪物；
普通旋风脉冲后：
必须同时产生径向和切向位移。

最终打击后：
方向必须重新以纯径向向外为主。
```

# 八、禁止实现

不得采用：

```text
只在上挑命中时额外增加一次伤害，
然后把它命名为跌落伤害；

在怪物开始下降时就提前结算落地伤害；

跌落伤害不考虑落地速度；

继续把目标位置大于初始位置作为传播通过标准；

只提高最大速度，但不提高实际初始冲量；

把所有传播怪物无条件设为相同速度；

让A、B、C在同一帧递归完成全部传播；

完全忽略怪物击退抗性；

让第一段旋风直接把所有怪推出攻击范围；

通过传送怪物位置伪装强力击退；

为了打散怪群而关闭怪物之间的碰撞。
```

最终体验必须是：

```text
上挑：
一大片怪物斜向飞出，
落地时再次受到清晰伤害。

旋风：
怪物先被卷动和加速，
随后互相撞击并向外传播动量，
终结打击把剩余怪群猛烈炸散。

A撞B，
B明显移动；

B撞C，
```
