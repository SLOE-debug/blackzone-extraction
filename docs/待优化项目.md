# 一、大锤动作奇怪：当前实现就是故意单手

## 根因已经非常明确

大锤原型目前写的是：

```ts
description: '沉重的单手战锤'
grip: WeaponGrip.OneHandHeavy
```

而整个通用装备层也只有：

```ts
WeaponGrip.OneHandHeavy
```

根本没有双手重武器类型。

角色姿态配置进一步明确规定：

```ts
const ONE_HAND_HEAVY_STANCE = stance(
  0, // leftInfluence
  1, // rightInfluence
  ...
);
```

即左臂完全不参与武器动画，右臂独自控制大锤。

测试甚至把这个错误需求固化了：

* 断言 `leftInfluence === 0`；
* 断言横扫时左手姿态完全不变；
* 测试名称就是“主角单手大锤姿势”。

所以当前表现不是偶发 bug，而是实现目标本身错了。

---

## 为什么胳膊肘看起来不弯

现有角色确实使用了 SoA，但 **SoA 只是数据布局，并不自动等于丝滑动画**。

当前 SoA 里只有：

```text
weaponPose
weaponAction
weaponActionProgress
weaponActionSide
最终 boneMatrices
```

没有这些动画状态：

```text
左右肩关节角速度
左右肘部弯曲量
左右手腕旋转
主握点与副握点约束权重
胸腔旋转速度
武器惯性和滞后量
动作阶段之间的过渡速度
```

动画系统每帧直接根据一个 `actionProgress` 计算关节点，然后马上写出最终骨骼矩阵。除了整体武器姿势混合之外，没有关节级的动态缓动或弹簧状态。

右肩、右肘、右腕和右手主要都是：

```ts
stanceTarget + attackOffset * attackAmount
```

再统一绕同一个 `weaponBodyYaw` 转动。它们缺少真正独立的肘部屈伸曲线，因此视觉上更像一条近似刚性的机械臂。

---

## 当前锤子也只约束了右手

新的锤头求解器只输入一个 `BattlefieldHammerGripPose`，注释明确写的是“角色右手 FK 输出的大锤主握点”。锤子的模型根和锤头位置都只从这个单一右手握点反解。

虽然角色 Rig 类型中存在 `SupportGrip`，但单手重武器的主握点和副握点目前全都是原点，副握点没有实际用途。

## 正确架构

应新增：

```ts
enum WeaponGrip {
  TwoHandHeavy = 'two-hand-heavy',
}
```

大锤原型应定义两个真实模型挂点：

```ts
held: {
  grip: WeaponGrip.TwoHandHeavy,
  mainGripLocalPosition,
  supportGripLocalPosition,
  hammerHeadLocalPosition,
}
```

动画流程应变成：

```text
动作时间轴
  ↓
生成锤头目标轨迹
  ↓
反解武器主握点和副握点世界位置
  ↓
右臂 Two-Bone IK → 主握点
左臂 Two-Bone IK → 副握点
  ↓
胸腔、肩膀、骨盆随发力方向分层旋转
  ↓
写入最终 SoA 骨骼矩阵
```

建议在 SoA 中增加连续状态，而不是逐帧直接覆盖：

```ts
weaponAnimation: {
  chestYaw: Float32Array;
  chestYawVelocity: Float32Array;

  leftElbowPoleX: Float32Array;
  leftElbowPoleY: Float32Array;
  leftElbowPoleZ: Float32Array;

  rightElbowPoleX: Float32Array;
  rightElbowPoleY: Float32Array;
  rightElbowPoleZ: Float32Array;

  mainGripWeight: Float32Array;
  supportGripWeight: Float32Array;
  hammerLag: Float32Array;
}
```

每只手臂用解析式 Two-Bone IK：

```text
肩 → 肘：固定上臂长度
肘 → 手：固定前臂长度
手 → 武器握点：硬约束
肘部朝向：由 elbow pole 控制
```

这样肘部一定会产生可见弯曲，而且动作转换可以使用临界阻尼，不会跳帧或突然伸直。

# 二、人物朝向离谱：根朝向可能正确，但视觉姿态被重复旋转

## 输入方向本身没有明显反向错误

攻击开始时，动作状态会用：

```ts
lockedHeading = Math.atan2(directionX, directionZ);
```

保存攻击方向。移动系统在挥动、恢复和技能期间直接使用这个 `lockedHeading`。

屏幕方向到世界方向的映射也与相机水平朝向一致，因此“摇杆上推却得到完全反方向”不是目前最明显的代码问题。

## 真正的问题是局部旋转被重复使用

动作层先计算：

```ts
weaponBodyYaw
```

然后它会同时影响：

* 骨盆；

* 胸腔；

* 颈部；

* 头部；

* 右肩；

* 右肘；

* 右手腕；

* 右手。

右手关节点已经按 `weaponBodyYaw` 转过一次之后，`writeVanguardWeaponRootFrame()` 又把同一个 `actionYaw` 作为武器根偏航再次写入。

随后锤头求解器又读取这个已经旋转过的武器根基向量，生成最终锤头方向。

结果相当于：

```text
角色根锁定到攻击方向
  +
右臂关节点局部旋转
  +
武器根再次旋转
  +
锤头轨迹在旋转后的基空间中计算
```

这会造成手、身体和锤头的视觉朝向彼此不一致。

旋风技能更严重：

```ts
weaponBodyYaw = progress * Math.PI * 6;
```

也就是角色根保持锁定不动，上半身相对双腿旋转三整圈。动画过程中上半身必然多次正对玩家反方向。

## 正确处理方式

横扫期间只保留一个权威攻击方向：

```text
attackHeading = atan2(attackX, attackZ)
```

角色根先平滑转向该角度，再锁定。身体局部扭转只负责表现蓄力：

```text
骨盆：攻击侧反向蓄力 10°–15°
胸腔：攻击侧反向蓄力 20°–35°
肩膀：随锤头轨迹移动
头部：尽量看向攻击目标
```

`WeaponRoot` 不应再次应用完整的 `weaponBodyYaw`，而应直接从双手的主、副握点构造朝向。

旋风则应让角色根朝向随技能角度旋转：

```ts
visualHeading = lockedHeading + spinAngle;
```

骨盆、胸腔、双臂和武器共享同一个旋转主体；锤子只增加少量惯性滞后。不能保持腿部不动，只让胸口和锤子转三圈。

# 三、技能按钮确实放反了

当前代码明确使用正 X 偏移：

```ts
Spin:
  centerX + orbitRadius

GroundSlam:
  centerX + diagonal

Uppercut:
  centerX
```

所以旋风和重砸位于右摇杆的右侧、右上侧。

对于右下角摇杆，这不仅不符合常见 MOBA 操作习惯，还会让按钮更靠近屏幕右边缘。

应沿 Y 轴镜像到摇杆左侧：

```ts
this.buttons[Spin].setPosition(
  centerX - orbitRadius,
  centerY,
);

this.buttons[GroundSlam].setPosition(
  centerX - diagonal,
  centerY + diagonal,
);

this.buttons[Uppercut].setPosition(
  centerX,
  centerY + orbitRadius,
);
```

对应屏幕角度是：

```text
180°：旋风
135°：裂地重砸
 90°：冲天上挑
```

也就是攻击摇杆左侧、左上侧和上侧，类似常见 MOBA 的技能扇区。

# 四、玩家开局持有大锤：装备与物品栏目前是两套互不相干的系统

物品栏初始化时五格全部为空。

但场景加载时会无条件创建：

```ts
new BattlefieldPlayerWeaponRuntime(...)
```

而该运行时的构造函数又无条件：

* 获取 `EquipmentId.Sledgehammer`；

* 创建大锤材质；

* 创建大锤手持 Renderer；

* 始终返回大锤握持姿态。

与此同时，宝箱又固定掉落一把大锤。

因此现在的实际状态是：

```text
角色手中：凭空存在一把大锤
物品栏：空
宝箱：还能再掉一把大锤
```

手持武器并不属于物品栏中的任何实例。

## 正确状态

开局应为：

```text
equippedItemInstance = null
weaponPose = Unarmed
技能按钮隐藏或禁用
手持装备 Renderer 不存在
```

流程应是：

```text
开宝箱
→ 大锤掉落到地面
→ 玩家拾取
→ 大锤进入物品栏
→ 玩家点击对应格子
→ 装备该物品实例
→ 创建大锤运行时与 Renderer
→ 显示大锤技能
```

推荐用稳定物品实例标识绑定装备，而不是绑定格子索引：

```ts
equippedInstanceSeed: number | null;
```

这样玩家拖动物品交换格子时，手持状态会跟随物品，而不是莫名切换到原格子里的新物品。

`BattlefieldPlayerWeaponRuntime` 需要变成可空的通用装备门面：

```ts
BattlefieldPlayerEquipmentRuntime {
  equippedItemId: EquipmentId | null;
  equippedInstanceSeed: number | null;

  equip(item): void;
  unequip(): void;
  updateActions(...): void;
}
```

没有装备时，武器 World System 直接跳过攻击、姿态和扫掠。

# 五、技能图标丑且不能随武器变化

当前三枚图标都是直接使用 `Graphics` 画的几根线：

* 旋风：一段圆弧加一个三角形；
* 重砸：一条竖线和几条折线；
* 上挑：一根箭头。

它们硬编码在 `BattlefieldRadialSkill` 中，与装备系统没有任何连接。

HUD 接收的也只是：

```ts
BattlefieldHammerStatus {
  hitCount;
  requiredHits;
  momentumReady;
  action;
  actionProgress;
}
```

其中没有：

* 当前装备 ID；
* 当前武器类型；
* 技能集合；
* 技能图标；
* 技能名称；
* 冷却状态。

物品栏也有同样的问题：任何已占用格都固定绘制一个锤子图案，完全不读取 `itemId`。

## 应改为武器原型驱动

```ts
interface EquipmentHudProfile {
  readonly inventoryIcon: EquipmentIconId;
  readonly skills: readonly WeaponSkillHudProfile[];
}

interface WeaponSkillHudProfile {
  readonly command: WeaponSkillCommand;
  readonly icon: SkillIconId;
  readonly label: string;
  readonly position: 0 | 1 | 2;
}
```

大锤原型注册：

```ts
hud: {
  inventoryIcon: EquipmentIconId.Sledgehammer,
  skills: [
    { command: Spin, icon: HammerWhirlwind, position: 0 },
    { command: GroundSlam, icon: HammerGroundSlam, position: 1 },
    { command: Uppercut, icon: HammerUppercut, position: 2 },
  ],
}
```

切换武器时：

```text
装备运行时发出 EquippedWeaponPresentation
→ HUD 替换三个技能图标
→ 替换技能行为
→ 替换充能/冷却显示
```

图标可以继续保持程序化渲染，但需要独立的高质量矢量轮廓模块；更合适的是统一 Sprite Atlas，避免在 HUD 类中手写折线。

无武器时三个按钮应隐藏，而不是仍然显示大锤技能。

# 六、底部物品栏目前只有“拖到锁定格”，没有切换和丢弃

现有拖拽逻辑只监听：

* `TOUCH_START`；
* `TOUCH_END`；
* `TOUCH_CANCEL`。

松手时只检查是否落在撤离锁定格上；命中才调用 `swapWithSecured()`，其他位置什么都不做。

物品栏运行时也只有：

```ts
tryInsert()
swapWithSecured()
createSnapshot()
```

不存在：

```text
选择格子
普通格互换
移除物品
拆分堆叠
装备物品
丢弃到世界
```

## 交互规则

推荐定义成：

```text
点击普通格
→ 切换/装备该格物品

拖到另一个普通格
→ 交换两个格子

拖到撤离锁定格
→ 与锁定格交换

拖出整个物品栏区域
→ 丢弃到玩家附近世界

取消触摸
→ 不产生任何物品变化
```

应增加明显拖拽反馈：

```text
原格半透明
手指位置显示物品幽灵
目标格高亮
拖出栏后显示红色“丢弃”状态
```

## 世界丢弃事务

当前世界掉落池拥有 `spawnBurst()`，但没有公开的玩家丢弃接口。

应新增：

```ts
treasures.trySpawnPlayerDiscard({
  equipmentId,
  instanceSeed,
  stackCount,
  originX,
  originY,
  originZ,
  directionX,
  directionZ,
}): boolean;
```

完整事务：

```text
1. 检查格子物品与数量
2. 检查世界掉落池是否有容量
3. 锁定物品栏转移
4. 在玩家前方生成掉落轨迹
5. 提交物品栏移除
6. 若丢弃的是手持武器，立即切换为 Unarmed
7. 更新技能 HUD
```

任何一步失败都必须回滚，不能出现复制或吞物品。

## 当前容量也需要重做

现在掉落池容量只根据：

```text
活动 Chunk 数
× 每 Chunk 最大宝箱数
× 每箱最大掉落量
```

计算，没有给玩家反复丢弃预留空间。

必须增加：

```ts
maximumPlayerDiscardedEquipment
```

或者为玩家丢弃维护独立固定池。否则连续拾取、丢弃最终会触发“超过预热固定容量”。

另外，目前地面 `instanceId` 在拾取时被直接当成物品栏 `instanceSeed`。

支持反复丢弃后，最好拆分：

```text
worldRuntimeId：当前地面实体身份
itemInstanceSeed：装备自身永久身份
```

这样物品从地面到背包、再丢回地面时，装备实例不会不断变成一件“新装备”。

# 必须修改的测试

现有测试正在验证错误的单手设计，必须删除或重写。

新的关键验收应包括：

* 双手到主、副握点的距离误差小于阈值；
* 左右肘关节角在合理范围内，并且挥动过程中明显变化；
* Windup、Swing、Recover 边界处关节位置没有跳变；
* 人物正面与攻击方向点积始终为正；
* 技能按钮全部位于右摇杆中心左侧或上侧；
* 开局物品栏为空且角色空手；
* 开箱、拾取、装备、切换、丢弃、重新拾取形成完整闭环；
* 切换武器后，技能图标和命令在同一帧完成替换；
* 拖拽取消、掉落池已满时不丢失物品。

当前最新提交把“锤头轨迹”做得比上一版正确，但它仍建立在“右手单握大锤”的错误基础上。继续调整现有几个坐标只会改善表象；双手握持、装备所有权和武器驱动 HUD 必须一起进入下一轮架构修正。
