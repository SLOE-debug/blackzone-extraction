# 猎场织网帧率波动分析与修复记录

## 问题结论

归弦猎弓的“猎场织网”会在固定 20Hz 查询帧中同步处理全部弦线。六支永久箭最多形成五条连续弦线，单次空间查询最多返回 512 个候选，因此查询热路径理论上需要处理最多 51,200 个候选/秒。

旧实现同时叠加了以下问题：

1. 生产路径常驻开启候选级诊断，每个候选都会重复计算投影和高度分类，并每两秒执行控制台表格输出。
2. 弦网复用了箭矢穿透所需的有序命中缓冲，每次命中都按进度插入并搬移 TypedArray；弦网本身没有顺序语义，最坏复杂度却达到 O(n²)。
3. 玩家移动或转向会让地面弦线和竖直引线被误判为需要重写，扩大 CPU 几何更新和 GPU Position Buffer 上传区间。
4. 弦网高度曾由 `owner.positionY` 推导，而怪物使用战场地面基准，导致视觉、查询和伤害坐标可能不在同一高度。
5. 弦网命中会在高密度怪群中集中创建伤害事件临时对象和校验数组，增加小游戏 JavaScript 运行时的 GC 压力。

这些工作集中发生在同一个 20Hz 查询帧内，能够解释技能开启后出现的周期性卡顿和帧率大幅波动。动态分辨率随后可能把 CPU 掉帧误认为像素压力并执行降档，使波动感进一步放大。

## 已实施修复

### 碰撞与伤害

- 新增弦网专用无序 SoA 命中缓冲，按 O(1) 直接追加目标。
- 缓冲仅保存目标标识和 XZ 接触点；命中 Y 统一来自固定弦网世界高度。
- 六支永久箭的最大弦线数由容量推导为五，不再保留不可达的第六条活动边。
- 弦网继续按 20Hz 在同一帧处理全部活动线段，不改变首次命中同步性、伤害数值、减速或逐线逐目标冷却。
- 弦网系统复用单个可变伤害事件对象，Damage Buffer 立即复制字段，命中循环不再逐目标创建事件对象。
- Damage Buffer 与弦网查询的高频参数校验改为标量判断，不再创建临时数组。

### 生产诊断

- 目标注册表默认不再创建弦网诊断器。
- 弦网诊断聚合器默认关闭，只允许测试或显式诊断入口注入并开启。
- 正式查询路径不会执行重复窄相位分类，也不会输出 `console.groupCollapsed()` 或 `console.table()`。

### 地面与渲染

- 战场地面、怪物脚底和弦网共享 `BATTLEFIELD_GROUND_Y`。
- 碰撞、伤害事件、地面弦线和怪物箭竖直引线共享 `BATTLEFIELD_TETHER_WORLD_Y`。
- 玩家 Y、移动和朝向不再参与地面弦线高度或更新判定。
- 弦线只在启停、锚点变化或对应箭矢位置 Dirty 时重写；颜色只在可见性变化时上传。
- 保留自定义引擎的 GPU Buffer 目标字节偏移能力，只上传实际 Dirty Range。

## 验证范围

自动测试覆盖：

- 无序命中缓冲保持追加顺序；
- 六支锚点生成五条弦线，并在同一查询帧完成五次判定；
- 20Hz 查询节奏和 0.45 秒冷却不变；
- 一条弦线能够伤害多个平面重叠目标；
- 玩家 Y 偏离地面时，真实 Registry 仍能完成查询、Damage Resolve 和怪物扣血；
- 诊断默认关闭，显式开启时仍能聚合输出；
- 碰撞高度与渲染高度使用同一常量。

最终性能结论需要使用用户生成的微信小游戏 Release 包，在 Android 与 iOS 真机关闭性能诊断后复测。验收时应对比同场景技能开启前后 FPS 与 P95 帧耗时，并确认不再出现与 20Hz 查询同步的周期性尖峰。
