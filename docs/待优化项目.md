# 一、挥动时左摇杆到底能不能控制玩家

## 能控制移动，而且普通挥动时还是全速移动

左摇杆会正常转换成世界移动方向，并写入：

```ts
intent.moveX
intent.moveZ
```

普通挥动没有降低移动速度；现在只有旋风技能会把移动速度缩放到 `0.36`，其他动作的缩放都是 `1`。

所以当前实际行为是：

```text
普通挥锤期间
  左摇杆控制位移：可以，而且是全速

  左摇杆控制人物朝向：不可以
```

这正是动作怪异的第一个根因。

---

# 二、挥动期间人物朝向被完全锁死

普通大锤的以下全部阶段都会产生 `HammerSwing` 朝向锁定：

```text
WindupLeft
SwingLeft
ChainPrepareLeft
WindupRight
SwingRight
ChainPrepareRight
Recover
```

也就是说，不仅锤头接触阶段锁定，连蓄力、连段准备和最终恢复期间也全部锁定。

移动系统检测到锁定后，会直接执行：

```ts
transform.heading = intent.lockedHeading;
continue;
```

它不是逐渐转向，也不是限制旋转速度，而是每帧硬写目标角度，随后完全忽略左摇杆的朝向意图。

当前调用链是：

```text
左摇杆
  → moveX / moveZ
  → 正常移动玩家

大锤 FacingLock
  → lockedHeading
  → 每帧直接覆盖人物 heading
  → 左摇杆无法改变人物朝向
```

因此玩家可以：

* 面朝怪物向侧面平移；
* 面朝怪物向后倒着移动；
* 在挥锤期间高速横穿人物朝向；
* 移动方向和身体、锤子方向完全不同。

这会产生很明显的“漂移”“滑步”“动作被扯着走”的感觉。

---

# 三、步态动画又完全不知道玩家在横移还是后退

当前主角动画只读取一个标量：

```ts
const speed = motion.speed[index];
```

它根据速度推进步态周期和移动混合，但没有读取：

* 实际速度 X/Z；
* 速度相对于人物朝向的前后分量；
* 速度相对于人物朝向的左右分量。

写姿态时也只传入了人物 `heading`、步态相位和速度混合，没有传入局部移动方向。

这意味着：

```text
人物面朝前方
左摇杆向左
实际位置向左移动

腿部动画：
仍播放普通前进步态
```

所以现在不是单纯“玩家不能转向”，而是：

> 玩家可以任意方向移动，但人物朝向被锤子锁死，腿部又始终播放正向行走。

这基本必然产生月球漫步、侧滑和身体被平移出去的感觉。

# 四、自动锁敌也在加剧朝向突变

最新代码里的右侧已经不是方向摇杆，而是无方向普通攻击按钮。真正决定攻击方向的是：

1. 附近自动锁敌；
2. 左摇杆移动方向；
3. 最后一次移动方向；
4. 当前人物朝向。

问题在于，目前自动锁敌没有方向权重。它会在以玩家为中心的完整圆形范围内直接选择**距离最近的存活怪物**。

当前大锤基础射程为 `3.9`，输入系统又增加了 `1.1` 的锁敌余量，所以自动锁敌范围约为：

```text
3.9 + 1.1 = 5.0
```

因此，以下情况完全可能发生：

```text
玩家正在向前移动
右后方 4 米处有怪物
该怪物是最近目标

按下攻击
  → 自动选择右后方怪物
  → 人物瞬间旋转到右后方
  → 左摇杆仍推动玩家向前
  → 人物倒着或横着滑动挥锤
```

## 连段之间也会重新计算方向

持续按住攻击时，输入系统会在下一击的预输入窗口再次执行自动瞄准，并缓存新的攻击方向。

下一击开始时：

```ts
this.lockedHeading = Math.atan2(directionX, directionZ);
```

直接把人物朝向换成新的方向。

虽然目标解析器会尽量保留原目标，但它每次都会使用目标的最新位置重新计算方向；目标死亡、离开范围或被替换时，下一次连段也可能突然转向另一只怪物。

所以这里的结论是：

> 挥动奇怪不是左摇杆完全失效，也不只是自动锁敌。主因是“全速任意移动 + 全阶段硬锁朝向 + 只有前进步态”，自动锁敌的全圆最近目标和连段瞬间换向又进一步放大了问题。

# 五、普通攻击的正确控制方案

不建议挥动期间彻底禁止移动。重武器完全定身会很僵，而且在怪群中很难生存。

正确做法是将“位移控制”和“身体转向”按动作阶段拆开。

## 建议的阶段配置

| 阶段           | 左摇杆移动 | 人物转向       | 自动锁敌   |
| ------------ | ----: | ---------- | ------ |
| Idle         |  100% | 跟随移动       | 正常搜索   |
| Windup       |   65% | 平滑转向目标     | 锁定本击目标 |
| Swing        |   35% | 基本锁定，仅允许微调 | 禁止换目标  |
| ChainPrepare |   55% | 有上限地转向下一击  | 可重新评估  |
| Recover 前半   |   55% | 保持本击朝向     | 不换目标   |
| Recover 后半   |   80% | 逐渐恢复到移动方向  | 释放目标   |

不要再使用：

```ts
heading = lockedHeading;
```

而应增加带最大角速度的软锁：

```ts
heading = moveAngleTowards(
  heading,
  desiredAttackHeading,
  maximumTurnRadiansPerSecond * deltaTime,
);
```

建议初值：

```text
Windup 最大转速：540°/s
Swing 最大转速：90°/s
ChainPrepare 最大转速：360°/s
Recover 后半：720°/s
```

这样玩家仍可以通过左摇杆调整位置，但锤头接触阶段不会因为玩家乱转而改变判定轨迹。

# 六、自动锁敌不能再使用“全圆最近怪物”

自动锁敌应该首先尊重左摇杆表达的意图。

## 推荐规则

玩家有左摇杆输入时：

```text
基础方向 = 左摇杆世界方向
只搜索基础方向左右各 70° 内的怪物
```

玩家没有左摇杆输入时：

```text
基础方向 = 当前人物朝向
只搜索左右各 100° 内的怪物
```

目标评分建议改成：

```ts
score =
  distanceSquared
  + angleDifference * angleWeight
  - preferredTargetBonus;
```

而不是现在只比较距离。

目标在人物身后时，不应该因为近了半米就让人物突然旋转 180°。

## 连段转向限制

每次下一击允许自动修正的最大角度建议控制在：

```text
普通连续攻击：每击最多修正 35°～45°
当前目标死亡：最多修正 70°
背后目标：不自动锁定
```

超过限制时，继续沿当前攻击方向，或者使用左摇杆方向。

这可以避免：

```text
左挥前方怪物
→ 下一击突然转到右后方
→ 整个人物与锤子瞬间扭转
```

# 七、需要增加二维移动动画

即使完成软锁，攻击时仍会存在一定程度的侧移和后退，所以动画系统不能再只有一个 `speed`。

建议在 SoA 中增加：

```ts
locomotionForward: Float32Array;
locomotionRight: Float32Array;
```

每帧计算：

```ts
forwardSpeed = dot(velocity, facingForward);
rightSpeed = dot(velocity, facingRight);
```

再驱动：

```text
向前：正常步态
向后：反向步态、步幅缩短
横移：腿向侧面跨步
斜向：前后与侧向混合
```

至少要做到：

* 面朝目标向左移动时，腿部播放左侧跨步；
* 向后移动时，步态相位反向或使用后退步态；
* 挥锤接触阶段压低重心；
* 不能继续让角色前进动画直接横向滑动。

# 八、旋风技能当前确实很慢

当前旋风参数是：

```ts
spinDurationSeconds = 2.6;
```

人物朝向在这段时间内旋转：

```ts
progress * Math.PI * 6
```

也就是总共三圈。

因此平均速度只有：

```text
3 圈 ÷ 2.6 秒
≈ 1.15 圈/秒
≈ 415°/秒
```

对于强调爆发和清场的旋风大锤，这个速度明显偏慢，视觉上更像缓慢转身挥锤，而不是高速旋风。

# 九、旋风期间玩家不仅慢，而且没有任何防御保护

旋风期间移动速度只有平时的：

```ts
0.36
```

而怪物攻击伤害结算不会检查玩家是否正在旋风，也没有任何：

* 伤害减免；
* 无敌帧；
* 霸体；
* 攻击打断免疫；
* 旋风状态防御系数。

怪物聚合伤害只要大于零，就会原样调用：

```ts
player.damage(damage);
```

所以当前旋风的实际体验是：

```text
持续 2.6 秒
移动速度只有 36%
每秒只转 1.15 圈
仍然承受 100% 怪物伤害
```

玩家当然会觉得自己是在怪物堆里缓慢送血。

# 十、推荐的高速旋风参数

建议把旋风明确设计成短时间爆发，而不是长时间持续。

```ts
spinDurationSeconds: 1.45,
spinRevolutions: 4,
spinMovementScale: 0.62,
spinDamageTakenScale: 0.45,
spinStartupSeconds: 0.1,
spinRecoverySeconds: 0.15,
```

对应平均旋转速度约为：

```text
4 圈 ÷ 1.45 秒
≈ 2.76 圈/秒
≈ 993°/秒
```

相比当前约快 `2.4` 倍。

建议阶段：

```text
0.00–0.10s
  双手抓紧、快速起转

0.10–1.30s
  高速有效旋转

1.30–1.45s
  减速恢复
```

## 防御效果

不建议完全无敌，推荐：

```text
旋风期间受到伤害 × 0.45
免疫普通受击硬直
仍然受到首领重击和环境伤害
```

这样可以保证技能能完成，但不会成为绝对安全按钮。

# 十一、旋风伤害窗口应与旋转角度绑定

当前伤害序列每 `0.32 秒`更新一次。

当旋转速度升级后，继续使用固定时间间隔会出现：

* 转得越快，每个伤害窗口跨越的圈数越多；
* 转速升级和伤害次数没有明确关系；
* 不同持续时间下总伤害难以控制。

更合理的是按照转过的角度更新命中序列：

```ts
spinHitWindowAngle = Math.PI;
```

即每转半圈创建一个新 `attackSequenceId`。

四圈技能便拥有八个命中窗口：

```text
每只怪物每半圈最多命中一次
四圈最多八次
```

视觉、转速与伤害频率天然统一。

旋风现在已经每帧使用真实锤头扫掠，并在同一攻击序列内对相同怪物去重，这个基础可以继续保留。

# 十二、高速旋风还需要扫掠子步进

当前动作时间单帧最多允许推进 `0.05` 秒。

若旋风速度提高到约 `1000°/秒`，最差单帧可能跨越约：

```text
1000°/秒 × 0.05 秒 = 50°
```

目前 Swept Capsule 只连接上一帧和当前帧锤头位置。高速圆周运动会被近似成一条弦：

```text
真实锤头轨迹：圆弧
当前扫掠：圆弧两端之间的直线
```

低帧率时可能切进圆心，漏掉圆弧外侧的一小段。

建议旋风碰撞按角度子步进：

```ts
const substepCount = clamp(
  Math.ceil(Math.abs(deltaSpinAngle) / degreesToRadians(15)),
  1,
  4,
);
```

每个子步都生成一段 Swept Capsule，但同一个伤害窗口继续使用相同序列 ID。

这样即使 30 FPS 或发生单帧抖动，也不会因为高速旋转而漏怪。

# 十三、建议新增统一动作控制配置

现在移动缩放和朝向锁分散在不同类里。建议建立：

```ts
interface HammerActionControlProfile {
  movementScale: number;
  facingPolicy: FacingPolicy;
  maximumTurnSpeed: number;
  autoTargetAllowed: boolean;
  damageTakenScale: number;
}

enum FacingPolicy {
  Free,
  SoftTarget,
  ContactLocked,
  SpinDriven,
}
```

例如：

```ts
const HAMMER_ACTION_CONTROL = {
  Windup: {
    movementScale: 0.65,
    facingPolicy: FacingPolicy.SoftTarget,
    maximumTurnSpeed: degreesToRadians(540),
    autoTargetAllowed: true,
    damageTakenScale: 1,
  },

  Swing: {
    movementScale: 0.35,
    facingPolicy: FacingPolicy.ContactLocked,
    maximumTurnSpeed: degreesToRadians(90),
    autoTargetAllowed: false,
    damageTakenScale: 1,
  },

  ChainPrepare: {
    movementScale: 0.55,
    facingPolicy: FacingPolicy.SoftTarget,
    maximumTurnSpeed: degreesToRadians(360),
    autoTargetAllowed: true,
    damageTakenScale: 1,
  },

  Spin: {
    movementScale: 0.62,
    facingPolicy: FacingPolicy.SpinDriven,
    maximumTurnSpeed: 0,
    autoTargetAllowed: false,
    damageTakenScale: 0.45,
  },
};
```

```text
左摇杆
  → 世界移动方向
  → 更新角色位移
  → 计算局部 forward/right 速度
```


# 十五、测试缺口

最新测试已经验证了：

* 按住两秒不出现 Idle 帧；

* 不同帧率下连段次数一致；

* 跨阶段剩余时间会被正确消费；

* 旋风使用真实锤头扫掠；

* 同一脉冲窗口不会重复伤害同一怪物。

但仍未覆盖：

1. 挥锤期间左摇杆移动与人物朝向的夹角；
2. 横移时腿部是否播放侧移步态；
3. 后退时是否出现正向走路的月球漫步；
4. 自动目标位于人物背后时是否突然转身；
5. 连段切换目标时最大朝向跳变量；
6. 旋风实际每秒转数；
7. 旋风期间玩家受到的伤害比例；
8. 高速旋风在 30 FPS 下是否漏掉圆弧外侧目标。
