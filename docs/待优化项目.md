## 1. 箭确实完全没有 Y 轴瞄准

这里已经可以直接定性。

传给弓运行时的参数中：

```ts
aimX: this.command.directionX,
aimY: 0,
aimZ: this.command.directionZ,
```

`aimY` 被硬编码成了 `0`，所以无论怪物高度、射击距离和箭的起点高度如何，箭都只会水平飞。箭的发射点默认在玩家 `Y + 2.45`，也就是说箭始终在大约胸口以上的固定高度平飞。

更严重的是，箭矢碰撞虽然接收三维起终点，但实际窄相位只计算 XZ 平面距离。`startY` 和 `endY` 没有参与碰撞判断，只在判断命中后用来插值得到一个 Y 坐标。因此，一支从怪物头顶很高处飞过的箭，只要 XZ 投影穿过怪物，也会被判定命中。

### 正确修法

不能只把 `aimY` 临时改成 `-0.08`。应该一起完成：

1. 右摇杆继续只控制 XZ 朝向。
2. 沿这个方向寻找最合适的怪物。
3. 只修正垂直瞄准，目标点取怪物躯干中心。
4. 没有目标时，瞄准远处大约 18～20 米位置、离地约 1.1～1.4 米的点。
5. 箭矢窄相位改成真正的三维线段与竖直胶囊体检测。

这样不会破坏“右摇杆直接控制攻击方向”，因为系统只辅助 Y 轴，不偷偷改变玩家的平面方向。

## 2. 箭悬浮在怪物上方的根因

当前命中时，命中位置的 Y 来自水平箭矢的弹道，所以通常是约 `2.45`。

但 `writeArrowTargetPose()` 返回的怪物 Y 永远是：

```ts
result.y = BATTLEFIELD_MONSTER_SPAWN.groundOffsetY;
```

也就是约 `0.05`，既没有怪物身体高度，也没有腾空高度。

随后附着偏移被计算成：

```ts
attachmentOffsetY = hitY - targetPose.y;
```

结果就会保存一个约 `2.4` 的垂直偏移。之后怪物移动时，箭始终保持在怪物地面坐标上方约 2.4 米，看起来当然像悬浮。

### 正确修法

`MutableBattlefieldArrowTargetPose` 不应只提供地面原点，应改成至少包含：

```ts
interface MutableBattlefieldArrowTargetPose {
  centerX: number;
  centerY: number;
  centerZ: number;
  radius: number;
  halfHeight: number;
}
```

其中：

```text
centerY = 地面高度 + 腾空高度 + 怪物身体中心高度
```

碰撞时计算箭线段与怪物竖直胶囊体的真实接触点。附着偏移应基于该身体中心保存：

```ts
offsetX = contactX - centerX;
offsetY = contactY - centerY;
offsetZ = contactZ - centerZ;
```

箭的方向继续保持命中前的飞行方向，使箭头真正进入表面，而箭杆留在外面。

第一版可以只跟随怪物平移和腾空；以后怪物存在明显身体旋转时，再把偏移转换到怪物局部坐标。

## 3. 怪物死亡后箭“消失”的根因

附着姿态查询只接受 `Alive` 怪物：

```ts
lifecycle === Alive
participation !== 0
```

怪物一进入 `Dying`，箭就立刻被认为失去目标。实际上项目已经有 `isMonsterLifecycleResident()`，它明确将 `Dying` 也视为仍然存在于画面中的生命周期，但箭矢查询没有使用它。

失去目标后，附着系统会这样处理：

```ts
arrows.positionY[index] = groundY;
arrows.state[index] = EmbeddedInWorld;
```

当前 `groundY` 默认是 `0`。箭原来的方向又是完全水平，所以整支箭立刻贴到甚至陷入地面，视觉上就像直接消失了。

射程耗尽落地也存在同一个问题：位置直接设为 `groundY`，没有任何视觉抬升或插地角度。

### 正确修法

生命周期分成两步处理：

**怪物进入 `Dying` 时**

* 箭继续附着在尸体上；
* `writeArrowTargetPose()` 使用 `isMonsterLifecycleResident()`；
* 姿态查询不再要求 Crowd `participation` 必须为 1；
* 箭跟随死亡动画或至少跟随尸体根位置。

**怪物进入 `DeathComplete` 或槽位即将回收时**

* 箭落到最后一次有效世界位置；
* 查询真实地面高度；
* 设置为 `groundY + 0.08～0.12`；
* 给箭一个轻微向下的方向，例如 `directionY = -0.25`；
* 清空 `attachedPopulationId`、`attachedEntityId` 和附着偏移；
* 再切换为 `EmbeddedInWorld`。

这样死亡过程中箭仍插在尸体上，尸体彻底消失后，箭才成为可见的地面箭。

## 4. 远处箭和弦线看不到

这不太像是批次包围盒没有扩张。当前 Renderer 会把全部活动箭位置计入包围盒，并不断扩大边界。更主要的问题是**箭和弦线太薄，而且很多时候正好处于地面内部**。

当前箭杆总宽度只有约 `0.07`，弦线半宽只有 `0.028`，总宽度约 `0.056`。弦线还是一张单独的水平色带，没有垂直厚度或朝向摄像机的 Billboard。放在 `Y = 0` 时非常容易和地面发生遮挡或深度冲突；距离一远，箭本身也会缩小到不足一个稳定像素。

### 正确修法

碰撞尺寸不变，只增强视觉尺寸：

* 地面箭视觉位置抬高 `0.08～0.12`。
* 弦线整体相对端点再抬高约 `0.06`。
* 弦线由一张水平色带改成两张交叉色带：

  * 一张水平；
  * 一张竖直；
  * 或直接使用朝向摄像机的色带。
* 弦线近距离宽度约 `0.06`，远距离插值到 `0.12～0.16`。
* 场上箭的视觉尺寸随与玩家距离从 `1.0` 放大到约 `1.5`。
* “猎场织网”激活期间，在每个锚点增加一个青色菱形或短柱状光标。

这不是单纯为了好看，而是技能所必需的信息可读性。玩家必须能判断锚点位置和连接关系。

## 5. 召回速度确实是固定的

现在自动召回固定为 `24`，技能召回固定为 `32`。每帧只选择其中一个固定速度，没有任何距离缩放。

对于 20 多米外的箭，`32` 的速度意味着返回动画会明显拖长；六支箭同时从远处返回时尤其迟缓。

### 推荐速度曲线

让当前距离越远，速度越高，但接近玩家时适当减速：

```ts
function calculateRecallSpeed(
  distance: number,
  minimumSpeed: number,
  maximumSpeed: number,
): number {
  const ratio = Math.max(0, Math.min(1, (distance - 4) / 20));
  const smooth = ratio * ratio * (3 - 2 * ratio);
  return minimumSpeed
    + (maximumSpeed - minimumSpeed) * smooth;
}
```

建议初始参数：

```text
自动召回：最低 28，最高 68
技能召回：最低 38，最高 88
```

效果大约是：

* 4 米以内：保持可读，不会瞬间消失；
* 10 米左右：明显比现在快；
* 20～24 米：高速回收；
* 接近角色后自然减速并收束。

原型字段最好从两个固定速度改成：

```ts
automaticRecallMinimumSpeed
automaticRecallMaximumSpeed
skillRecallMinimumSpeed
skillRecallMaximumSpeed
recallAccelerationDistance
```

## 测试也需要一起修

目前测试中的 `OWNER.aimY` 就是明确写死的 `0`，等于把错误的水平弹道当作合法基准。怪物死亡测试也只验证了 XZ 不变，没有检查落地后的 Y、方向和箭是否处于地面之上。

至少新增这些测试：

1. 面向怪物射击时，箭拥有非零 `directionY`。
2. XZ 投影穿过怪物、但高度高于怪物时不得命中。
3. 命中后箭的位置位于怪物胶囊表面附近。
4. 怪物进入 `Dying` 后箭继续跟随。
5. `DeathComplete` 后箭落地，且 `positionY > groundY`。
6. 同一帧内，远距离箭的召回位移大于近距离箭。
7. 最大射程位置的箭和弦线拥有足够的视觉宽度和有效 Alpha。

## 推荐修改顺序

先修 **三维瞄准、三维碰撞和怪物姿态高度**；这会同时解决水平飞行和悬浮附着。随后修死亡生命周期与地面落箭，最后再增强远距视觉和距离召回曲线。

建议合成一个提交：

```text
fix: 修正猎弓三维弹道、附着生命周期与远距召回表现
```

这些问题的共同核心不是数值没调好，而是当前猎弓虽然数据结构是三维的，关键判定仍然按照二维 Crowd 逻辑实现。先把这层补完整，后续穿透、织网、腾空怪物和附着模块才不会继续出现类似问题。
