## 结论先说

前两个“图标已经出现，松手却没反应”的共同根因很可能是：

> **系统把“按住预览”和“松手执行”当成两个独立帧处理，但松手可能被取消、失效或被障碍判定拒绝；失败后没有任何玩家可见反馈。**

第三个问题则更直接：

> **毒液蛋怪目前根本没有接入抓取系统，所以无论剩多少血都抓不了。**

# 1. 向角色背后抓取：图标出现，松手没反应

最新代码已经不再要求松手时继续正对目标。

抓取锁定后，松手阶段会跳过方向检查，只重新检查：

* 目标是否仍然具备抓取资格；
* 距离是否小于 `4.1`；
* 路径是否仍然畅通。

所以你描述的现象不再是单纯的“角色朝向限制”。

## 最可疑问题一：`TOUCH_CANCEL` 会直接吞掉技能

技能轮盘在正常 `TOUCH_END` 时会保存一份 `released` 输入：

```ts
this.queueRelease(...);
```

但 `TOUCH_CANCEL` 只会：

```ts
this.touchId = null;
this.resetAxis();
```

完全不会产生释放事件。

而抓取真正执行的必要条件就是：

```ts
intent.released === true
```

没有释放事件，它只会清除锁定，不会抓取。

这会形成非常符合你描述的流程：

```text
按住技能
→ 找到怪物
→ 显示可抓取标志

手指向右上方拖动
→ UI 收到 TOUCH_CANCEL，而不是 TOUCH_END

下一帧
→ active = false
→ released = false
→ 清除目标锁
→ 什么都不发生
```

同时控制移动摇杆时属于多点触控场景，更容易暴露触摸所有权、节点重叠或取消事件问题。

### 修法

技能轮盘不应该把所有 `TOUCH_CANCEL` 都视为放弃技能。

至少要区分：

* 系统中断、界面销毁：真正取消；
* 手势离开命中区域、触摸被转移：按照最后有效输入释放；
* 玩家主动拖入取消区域：取消。

第一版最直接的修法：

```ts
private handleActionCancel(event: EventTouch): void {
  if (event.getID() !== this.touchId) {
    return;
  }

  this.queueRelease(this.inputX, this.inputY, this.amplitude);
  this.touchId = null;
  this.resetAxis();
}
```

然后再单独设计明确的取消区域。

## 最可疑问题二：显示标志后，最终验证仍可能失败

虽然已经锁定目标，但玩家在继续向右下方移动。

松手帧会使用玩家移动后的最新位置，再检查：

```ts
distance <= 4.1
```

以及玩家到目标之间的路径。

玩家向右下移动，而目标位于右上，相当于正在远离目标。如果目标本来就在抓取范围边缘，松手时就可能超过保持距离。

问题在于，失败只产生内部的 `GrabCancelled` 事件，界面上没有：

* 距离超限提示；
* 障碍阻挡提示；
* 锁定断裂动画；
* 失败音效。

而且抓取预览只在 `intent.active` 时写入。松手时即便最终验证失败，也不会产生一帧红色无效预览。

玩家体验就是：

> 明明上一瞬间有图标，松手却像没按一样。

### 修法

锁定建立后，建议使用两层范围：

```text
获取范围：3.8 米
普通保持范围：4.1 米
松手容错范围：4.4～4.6 米
```

并且最终失败必须写出原因：

```ts
enum GrabFailureReason {
  None,
  TouchCancelled,
  TargetInvalid,
  OutOfRange,
  PathBlocked,
  BeginCarryRejected,
}
```

至少在 Debug HUD 中显示最后一次失败原因。

## 另一个表现问题：抓到背后目标后，怪物会被放到角色正前方

携带位置完全根据 `player.heading` 计算：

```ts
x = player.x + sin(heading) * offset;
z = player.z + cos(heading) * offset;
```

它不参考抓取技能方向。

所以玩家朝右下移动、向右上抓怪时，即便抓取成功，怪物也会瞬间从右上被拉到角色朝向的右下方。

这可能使成功反馈看起来很怪，甚至让玩家误以为没有抓到。

建议抓取成功时先保存：

```text
grabDirectionX
grabDirectionZ
```

抓取动画期间沿抓取方向拉向玩家，完成后再逐渐过渡到角色携带锚点，而不是第一帧直接瞬移到角色正前方。

# 2. 抓住怪后，向某些方向投掷没反应

这里至少有三个静默失败出口。

## 原因一：同样可能是 `TOUCH_CANCEL`

投掷也只在 `intent.released` 时真正执行。

所以技能预览已经出现，但触摸最后进入 `TOUCH_CANCEL`，投掷仍然会被完全吞掉。

这个问题抓取、投掷共享，不是两个独立 Bug。

---

## 原因二：轨迹不足 3.2 米时，直接不执行

投掷要求最终合法距离至少为：

```ts
MINIMUM_THROW_DISTANCE = 3.2;
```

如果三维障碍预测将轨迹截短到不足 3.2 米：

```ts
const valid = distance >= MINIMUM_THROW_DISTANCE;

if (!intent.released || !valid) {
  return;
}
```

投掷会直接返回，没有失败事件，也没有提示。

如果轨迹第一段就被判定阻挡，`blockedProgress` 会变成零，随后候选距离直接归零。

这也是标准的：

> 按钮按了，但什么都没发生。

---

## 原因三：携带怪物的位置没有做环境碰撞约束

携带怪物固定放在角色朝向前方 `1.05` 米、高 `1.7` 米的位置，并没有经过环境碰撞解析。

假设玩家朝右下移动，靠近一块岩石或树：

```text
玩家脚下是合法位置
但角色前方 1.05 米可能已经进入障碍体
```

怪物仍会被强行放进去。

此时你向右上，也就是反方向投掷，轨迹从这个可能与障碍相交的携带点开始。三维预测第一段便可能判定阻挡，最终距离归零。

这能解释为什么：

* 不是每次都失败；
* 与玩家当前朝向有关；
* 与投掷方向有关；
* 移动过程中更容易出现。

### 修法

携带锚点必须先做一次空间解析：

```ts
desiredCarryPosition
→ resolveSpatial(...)
→ resolvedCarryPosition
```

如果正前方无法放下怪物，可以：

1. 缩短携带偏移；
2. 向更高处抬升；
3. 在玩家周边寻找最近合法携带槽位；
4. 最差情况下保持上一帧合法携带位置。

投掷轨迹还应忽略起点附近的初始重叠，或者先将投掷物推出当前障碍再开始正式扫掠。

---

## 输入死区也有不一致

输入层把小于 `0.18` 的技能拖动视为无方向，并将投掷幅度写成零。

但投掷模块自己的最低幅度是 `0.12`。

因此 `0.12～0.18` 这段配置实际上永远用不到。

这不是主因，但说明输入职责分散了。Dead Zone 应该只由输入层统一处理，投掷模块接收的应当是已经重映射后的有效幅度。

# 3. Venom Lobber 为什么完全抓不了

这个问题已经确认：**不是血量阈值 Bug，而是根本没有接入抓取协议。**

当前初始化中，Venom Lobber 只注册到了：

* Crowd；
* Target Registry。

没有注册到 `BattlefieldMonsterManipulationRegistry`。

Curve Crawler 则明确注册到了 Manipulation Registry。

同时 `BattlefieldVenomLobberGroup` 只实现：

```ts
BattlefieldMonsterTargetGroup
```

没有实现：

```ts
BattlefieldMonsterManipulationGroup
```

也完全没有：

* `writeManipulationCandidateForEntity`
* `beginCarry`
* `beginThrow`
* `synchronizeManipulatedPose`
* `releaseManipulation`
* `killManipulated`

相关接口。

所以它即便剩余 1% 生命，也不会成为抓取候选。

## 需要补的不是一个布尔值

Venom Lobber 需要完整接入操作状态：

```text
ManipulationState
Grabbable
PlayerGrabbable
BodySize
ExecutableHealthRatio
GrabResistance
ThrowMass
MaximumThrowDistance
CollisionRadius
ImpactStrength
CombatTags
CrowdParticipation
```

还要在行为、移动、攻击和毒液投射系统中统一处理：

```ts
if (manipulationState !== Free) {
  停止移动;
  停止攻击;
  取消正在蓄力的毒液蛋;
}
```

否则抓起之后，它可能还会在玩家头顶继续施法。

### 设计上还需要先决定

Venom Lobber 看起来比 Curve Crawler 更重，建议不要照搬相同参数。

可以设置为：

```text
生命低于 35% 才可抓取
体型：Medium
抓取动作时间更长
投掷距离更短
撞击质量更高
被投掷时毒囊发生特殊反应
```

这样它不只是“另一只也能抓的怪”，而是能产生你想要的 ECS 组合：

```text
Venom Lobber
+ Thrown
+ GroundImpact
= 毒囊破裂，生成强化毒池
```

# 当前测试为什么没抓住这些问题

最新回归测试验证的是：

* 抓取预览后，松手方向轻微变化仍能抓；
* 使用假的怪物 Gateway；
* 固定玩家位置；
* 正常 `released` 输入。

它没有覆盖：

* 移动摇杆与技能手势同时操作；
* `TOUCH_CANCEL`；
* 玩家朝目标反方向持续移动；
* 携带锚点进入障碍；
* 向角色背后投掷；
* 轨迹被截短到 3.2 米以下；
* Venom Lobber 抓取。

因此自动化测试通过，并不代表你描述的真实触控流程已经成立。

# 修复优先级

**P0**

1. `TOUCH_CANCEL` 不得静默吞掉技能，记录并区分取消原因。
2. 抓取和投掷失败必须产生可见或 Debug 可见的失败原因。
3. 携带锚点接入三维环境约束。
4. 为真实多点触控增加输入测试。
5. 为 Venom Lobber 接入完整 Manipulation Group。

**P1**

1. 抓取成功后沿抓取方向播放拉拽过程，不要立即跳到角色朝向。
2. 松手抓取增加距离容错。
3. 投掷允许短距离砸地，而不是不足 3.2 米就完全没反应。
4. 统一输入层与投掷模块的 Dead Zone。

目前最值得先改的是 **`TOUCH_CANCEL` 和失败原因诊断**。现在大量失败路径都表现为“什么都没发生”，导致不同问题在玩家眼里完全一样。
