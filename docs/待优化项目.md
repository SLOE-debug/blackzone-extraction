# 旋风伤害、怪群动量传播与全怪物掀飞重构方案

## 一、产品定位

旋风不能只是：

```text
玩家无敌
→ 周围怪物受几次伤害
→ 怪物被分别推开
```

正确体验应该是：

```text
玩家冲进怪群启动旋风
→ 内圈怪物被连续加速并甩向外侧
→ 内圈怪物撞开外圈怪物
→ 外圈怪物继续携带部分动量向外传播
→ 整个怪群像被投入一颗动能炸弹一样层层崩开
```

旋风的核心产品身份定义为：

> 高伤害、全程无敌、延迟爆散、可以通过怪物碰撞传播动量的怪群破阵技能。

它不只是范围伤害技能，而是大锤构筑中的“战场重置按钮”。

# 二、旋风伤害重构

## 2.1 当前伤害不足

当前配置：

```ts
SpinPulse = 0.34 * baseDamage
SpinFinal = 0.88 * baseDamage
```

完整持续命中约为：

```text
7 × 0.34 + 0.88 = 3.26 倍基础伤害
```

建议首轮目标：

```text
完整贴身命中同一目标：
总直接伤害约 4.5～5.1 倍基础伤害
```

因为旋风需要积累资源才能释放，并且需要玩家主动进入怪群，这个强度是合理的。

## 2.2 使用重复命中递增伤害

不要简单地把所有脉冲统一从 `0.34` 改成一个大数。

新增每个怪物在本次旋风中的命中次数：

```ts
spinHitSkillSequence: Uint32Array;
spinHitCount: Uint8Array;
```

增加接口：

```ts
recordSpinHit(
  populationId: number,
  entityId: number,
  skillSequenceId: number,
): number;
```

规则：

```ts
if (lastSequence !== skillSequenceId) {
  lastSequence = skillSequenceId;
  hitCount = 0;
}

hitCount++;
return hitCount;
```

伤害倍率：

```ts
function calculateSpinPulseDamageScale(
  targetHitCount: number,
): number {
  const base = 0.42;
  const repeatBonus = Math.min(
    Math.max(0, targetHitCount - 1) * 0.06,
    0.24,
  );

  return base + repeatBonus;
}
```

结果：

```text
第一次：0.42
第二次：0.48
第三次：0.54
第四次：0.60
第五次及以后：0.66
终结打击：1.05
```

理论完整命中：

```text
0.42 + 0.48 + 0.54 + 0.60
+ 0.66 + 0.66 + 0.66 + 1.05
= 5.07 倍基础伤害
```

这样玩家把怪物持续留在旋风范围内时，会获得明显的伤害爬升。

## 2.3 配置化

在 `SledgehammerProgressionStats` 增加：

```ts
readonly spinPulseBaseDamageScale: number;
readonly spinRepeatDamageStep: number;
readonly spinRepeatDamageMaximumBonus: number;
readonly spinFinalDamageScale: number;
```

推荐初始值：

```ts
spinPulseBaseDamageScale: 0.42,
spinRepeatDamageStep: 0.06,
spinRepeatDamageMaximumBonus: 0.24,
spinFinalDamageScale: 1.05,
```

删除 `battlefield-hammer-impact-profile.ts` 中旋风伤害的硬编码数字。

# 三、将“磁化碰撞”重构为“动量载体”

## 3.1 当前机制必须废弃

当前机制存在三个错误：

```text
只有两个都被旋风命中的怪物才能碰撞；
外层未被命中的怪物不能接收动量；
碰撞后把已有速度覆盖成固定速度。
```

删除或停止使用以下概念：

```ts
magnetizedRemaining
magnetizedSequence
resolvedMagnetizedPairs
resolveMagnetizedCollisions()
writeCollisionKnockback()
```

新系统命名建议：

```text
Kinetic Carrier
动量载体
```

## 3.2 动量载体状态

在怪物通用 Effect SoA 中新增：

```ts
kineticSequence: Uint32Array;
kineticRemaining: Float32Array;
kineticGeneration: Uint8Array;

/** 本次技能允许造成的剩余碰撞伤害预算。 */
kineticDamageBudget: Float32Array;
```

怪物被旋风直接命中后：

```ts
kineticSequence[id] = skillSequenceId;
kineticRemaining[id] = 0.7;
kineticGeneration[id] = 0;
kineticDamageBudget[id] = baseDamage * 0.9;
```

任何被动量载体撞开的怪物，也会成为新的动量载体。

# 四、动量传播规则

## 4.1 任意怪物都能接收传播

碰撞条件修改为：

```text
来源怪物：
属于当前旋风的动量载体；
当前实际平面速度大于最低传播速度。

目标怪物：
存活；
参与 Crowd；
不是来源自身；
不要求曾被旋风直接命中。
```

即：

```text
内圈怪物撞到未被锤子命中的外圈怪物时，
外圈怪物也必须被撞开。
```

## 4.2 使用相对速度和碰撞法线

读取来源当前实际速度向量：

```ts
sourceVelocityX = sourceDirectionX * sourceCurrentSpeed;
sourceVelocityZ = sourceDirectionZ * sourceCurrentSpeed;
```

计算来源到目标的碰撞法线：

```ts
normalX = targetX - sourceX;
normalZ = targetZ - sourceZ;
normalize(normalX, normalZ);
```

计算闭合速度：

```ts
closingSpeed =
  sourceVelocityX * normalX
  + sourceVelocityZ * normalZ
  - targetVelocityX * normalX
  - targetVelocityZ * normalZ;
```

只有：

```ts
closingSpeed >= minimumPropagationSpeed
```

才发生动量传播。

推荐：

```ts
minimumPropagationSpeed: 3.2
```

## 4.3 传递速度

推荐第一版：

```ts
const transferRatio = 0.68;
const sourceRetention = 0.74;

const transferredSpeed =
  closingSpeed
  * transferRatio
  * targetKnockbackResistance;
```

目标获得：

```ts
targetVelocity += collisionNormal * transferredSpeed;
```

来源保留：

```ts
sourceVelocity *= sourceRetention;
```

目标成为下一层载体：

```ts
target.kineticSequence = source.kineticSequence;
target.kineticRemaining = Math.max(
  target.kineticRemaining,
  source.kineticRemaining * 0.82,
);
target.kineticGeneration =
  source.kineticGeneration + 1;
```

注意：

```text
不能把来源和目标速度写成固定6.5；
不能删除来源已有速度；
必须按速度向量进行叠加。
```

## 4.4 连续传播

新获得动量的目标从下一帧开始传播。

不要在同一帧使用递归或 BFS 立即穿透整群怪物。

正确视觉节奏：

```text
第1帧：内圈撞中第二圈；
第2帧：第二圈开始移动；
第3～5帧：冲击波继续扩散。
```

这样玩家能看清一层层向外崩开的动量波，而不是怪群同一帧集体瞬移。

## 4.5 传播衰减和安全上限

推荐参数：

```ts
kineticDurationSeconds: 0.7,
kineticTransferRatio: 0.68,
kineticSourceRetention: 0.74,
kineticMinimumSpeed: 3.2,
kineticMaximumSpeed: 38,
kineticMaximumGeneration: 8,
kineticMaximumCarriersPerSkill: 96,
kineticPairCooldownSeconds: 0.1,
```

传播主要通过速度自然衰减停止。

`maximumGeneration` 和载体数量只作为极端怪群场景的性能保险，不应成为正常战斗中肉眼可见的截断。

# 五、碰撞伤害规则

动量必须持续传播，但伤害不能指数爆炸。

## 5.1 直接锤击和碰撞伤害分离

直接被旋风锤头命中的怪：

```text
承受完整旋风直接伤害；
获得最高初始动量。
```

被其他怪撞中的目标：

```text
承受较低的动能碰撞伤害；
获得传播后的速度；
可以继续撞向下一层。
```

碰撞伤害公式：

```ts
const normalizedSpeed = clamp(
  closingSpeed / 30,
  0,
  1,
);

const collisionDamageScale = lerp(
  0.12,
  0.45,
  normalizedSpeed,
);

const requestedDamage =
  baseDamage * collisionDamageScale;
```

使用每个载体的伤害预算限制：

```ts
const appliedDamage = Math.min(
  requestedDamage,
  source.kineticDamageBudget,
);

source.kineticDamageBudget -= appliedDamage;
```

这样可以出现连锁碰撞伤害，但不会因为一只怪连续撞十只怪而产生无限伤害。

## 5.2 碰撞去重

当前“一对怪物整次技能只能碰撞一次”过于僵硬。

改成短时间冷却：

```text
同一对怪物在0.1秒内只结算一次传播；
分开后重新碰撞可以再次结算。
```

碰撞伤害可以限制得更严格：

```text
同一对怪物每次技能最多造成一次碰撞伤害；
但后续仍允许继续传递速度。
```

即：

```text
力可以持续传播；
伤害受到预算和去重限制。
```

# 六、使用 Crowd 空间哈希，不得继续全量两两扫描

当前碰撞检测会遍历全部 Effect 群体中的实体组合。

怪群规模提升后，不能在此基础上继续增加传播层数。

## 6.1 注入空间查询门面

让 `BattlefieldMonsterEffectRuntime` 接收：

```ts
PlanarCrowdSeparationSystem
```

或只读接口：

```ts
export interface PlanarCrowdCollisionSource {
  collectSegmentCandidates(...): number;
  collectCircleCandidates(...): number;
}
```

## 6.2 使用扫掠线段查询

每个活动动量载体保存上一帧与当前帧位置。

使用：

```ts
collectSegmentCandidates(
  previousX,
  previousY,
  currentX,
  currentY,
  sourceRadius,
  candidateBuffer,
);
```

再执行精确线段或圆形接触判断。

这样同时解决：

```text
高速怪物穿过外圈目标；
旋风击退提高后碰撞漏判；
全量O(N²)扫描。
```

只处理真实高速移动载体附近的候选怪物。

# 七、旋风击退加强，但采用“先卷入、后爆散”

单纯提高每次脉冲的击退，会让怪物第一下就飞出攻击范围，反而降低旋风伤害。

推荐按照旋风进度增强击退：

```ts
function calculateSpinPulseKnockbackScale(
  spinProgress: number,
): number {
  return lerp(
    0.72,
    1.08,
    spinProgress * spinProgress,
  );
}
```

推荐参数：

```ts
spinKnockbackImpulse: 13.5,
spinPulseMinimumKnockbackScale: 0.72,
spinPulseMaximumKnockbackScale: 1.08,
spinFinalKnockbackScale: 1.65,
spinMaximumKnockbackSpeed: 38,
spinKnockbackDurationSeconds: 0.4,
```

实际表现：

```text
前几圈：
怪物被卷开，但仍有机会继续吃到伤害。

中后段：
速度明显提升，内圈怪开始撞向外圈。

最终打击：
一次强力径向爆散，把残余怪群彻底炸开。
```

终结打击推荐初始速度约：

```text
13.5 × 1.65 ≈ 22.3
```

重复命中、碰撞传递后允许达到最大速度 38。

# 八、修复“只有蜘蛛明显掀飞”

## 8.1 不再使用单一 airborneResistanceScale

当前一个参数同时缩放：

```text
水平飞行速度；
垂直初速度；
最终腾空高度。
```

这个产品契约不正确。

拆分成：

```ts
export interface MonsterLaunchResponse {
  readonly launchable: boolean;

  /** 目标腾空高度倍率。 */
  readonly heightScale: number;

  /** 水平飞行速度倍率。 */
  readonly horizontalScale: number;

  /** 普通平面击退倍率。 */
  readonly knockbackScale: number;
}
```

`BattlefieldMonsterTargetGroup` 改为：

```ts
readonly launchResponse:
  Readonly<MonsterLaunchResponse>;
```

## 8.2 使用目标高度，而不是缩放垂直速度

将 `DirectionalLaunchEffect` 修改为：

```ts
export interface DirectionalLaunchEffect {
  readonly directionX: number;
  readonly directionZ: number;

  readonly targetHeight: number;
  readonly horizontalSpeed: number;
  readonly horizontalDrag: number;
  readonly gravityScale: number;
}
```

运行时：

```ts
const effectiveHeight = Math.max(
  effect.targetHeight
    * group.launchResponse.heightScale,
  minimumVisibleLaunchHeight,
);

const verticalSpeed = Math.sqrt(
  2 * gravity * effectiveHeight,
);
```

不要执行：

```ts
verticalSpeed *= resistance;
```

因为高度会变成 resistance 的平方。

## 8.3 当前怪物推荐参数

Curve Crawler：

```ts
launchResponse: {
  launchable: true,
  heightScale: 1,
  horizontalScale: 1,
  knockbackScale: 1,
}
```

Venom Lobber：

```ts
launchResponse: {
  launchable: true,
  heightScale: 0.72,
  horizontalScale: 0.78,
  knockbackScale: 0.58,
}
```

以 4.2 米基础高度计算：

```text
Venom 实际目标高度约3.0米。
```

它应该看起来更沉、更慢，但仍然必须明显离地并沿受击方向飞出去。

## 8.4 所有普通怪物默认可掀飞

规则：

```text
只要类型属于普通 Monster，
默认必须支持方向腾空。
```

不得用：

```ts
airborneResistanceScale = 0
```

来隐式表示免疫。

未来若确实需要 Boss 或建筑型单位免疫，必须使用显式能力：

```ts
launchable: false
```

并设计对应的替代反馈，例如：

```text
强制硬直；
破韧；
地面滑退；
专属重击反馈。
```

当前已有怪物类型全部设置为：

```ts
launchable: true
```

# 九、统一怪物群注册，避免新怪漏接 Effect

当前每增加一种怪物，都需要手动分别注册：

```text
Crowd
Target Registry
Effect Runtime
```

容易出现“能被攻击，但不能腾空”的半接入状态。

新增统一注册门面：

```ts
class BattlefieldMonsterWorldRegistry {
  register(group: BattlefieldMonsterTargetGroup): void {
    crowd.register(group.crowdPopulation);
    targets.register(group);
    effects.register(group);
  }

  unregister(group: BattlefieldMonsterTargetGroup): void {
    effects.unregister(group);
    targets.unregister(group);
    crowd.unregister(group.populationId);
  }
}
```

正式波次、专家怪和 Debug 怪全部通过同一个门面注册。

不得再在不同类中手写三次注册流程。

# 十一、必须增加的测试

## 11.1 旋风完整伤害

```text
同一目标连续命中7次脉冲和1次终结；
每次脉冲伤害逐步提高；
最终总倍率约为5.07；
不同技能序列必须重置命中次数。
```

## 11.2 外层未命中怪物也被撞开

```text
A被旋风直接击中并高速向右运动；
B没有被旋风命中；
A撞到B；
B必须获得向右速度并成为动量载体。
```

## 11.3 连续传播

```text
A撞B；
下一帧B撞C；
C必须获得速度；
C继续撞D时仍能传播。
```

## 11.4 不能撞墙式降速

```text
A当前速度为20；
A撞到静止B；
结算后A不得被无条件改成6.5；
A和B总动量应在衰减范围内保持连续。
```

## 11.5 反方向与侧向碰撞

```text
同方向碰撞：目标加速；
侧向碰撞：速度方向发生偏转；
反方向碰撞：来源先减速，不能穿透目标。
```

## 11.6 传播伤害预算

```text
同一来源连续撞击多只怪；
总碰撞伤害不得超过其kineticDamageBudget；
速度仍允许继续传播。
```

## 11.7 Curve Crawler 掀飞

```text
上挑后水平位移和腾空高度均明显大于零；
目标高度接近基础配置。
```

## 11.8 Venom Lobber 掀飞

必须使用真实 `BattlefieldVenomLobberGroup` 或真实怪物夹具：

```text
上挑后 externalAirborneActive = 1；
目标世界腾空高度峰值不得低于2.4米；
水平位移明显大于零；
腾空期间停止自主移动和攻击；
落地后恢复行为。
```

## 11.9 每种 BattlefieldMonsterId 集成测试

遍历所有怪物 ID：

```ts
for (const monsterId of ALL_BATTLEFIELD_MONSTER_IDS) {
  spawn(monsterId);
  applyDirectionalLaunch(...);
  expect(monster).toBecomeAirborne();
}
```

新增怪物类型但没有接入腾空时，测试必须直接失败。

## 11.10 性能测试

```text
500只怪；
最多96个活动动量载体；
传播更新不得执行全量实体两两组合；
候选数量与局部空间密度相关；
热路径不得创建临时数组、对象或Set。
```

# 十二、验收场景

在玩家周围生成三层怪群：

```text
内圈：10只
中圈：20只
外圈：30只
同时包含蜘蛛和Venom Lobber
```

玩家进入内圈释放旋风。

必须观察到：

```text
1. 旋风持续命中时伤害逐渐提高；
2. 内圈怪物逐渐被加速；
3. 内圈怪物撞向中圈后，中圈被撞开；
4. 中圈继续撞向外圈，形成可见传播波；
5. 外圈不能表现成静止墙体；
6. 旋风后半和终结打击明显把怪群打散；
7. 蜘蛛和Venom都能被群体上挑；
8. Venom飞得可以更低、更慢，但必须明显离地；
9. 传播不会产生无限伤害或永久高速怪物；
10. 大规模怪群下帧率不因碰撞传播明显下降。
```

最终玩家感受应该是：

> 我不是在原地转圈刮伤害，而是把内圈怪物当成炮弹，向外层怪群连续砸出了一道动量冲击波。
